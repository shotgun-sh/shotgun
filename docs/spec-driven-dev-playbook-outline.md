## Slide-by-Slide Breakdown

### Hero Slide: Title + Hook
- **Type**: Hero slide
- **Content**:
  - Main title: "Spec-Driven Development + AI-Assisted Coding Playbook"
  - Subtitle/hook: "When planning mode in Claude Code/Cursor is not enough"
- **Design notes**: Bold typography, minimal text, Shotgun branding prominent

---

### Slide 1: Who This Is For (AUDIENCE)
- **Type**: Audience identification / list
- **Content**:
  - 3 bullet points identifying target readers
  - Closing statement connecting to value
- **Design notes**: Icon-based list, scannable format

---

### Slide 2: The Problem (PROBLEM)
- **Type**: Problem statement
- **Content**:
  - Opening challenge: LLM-assisted coding is hard for complex work
  - "Plan mode" works for small stuff, breaks for large features
  - Key pain points: context loss, rebuilding, drift
  - Transition statement to solution
- **Design notes**: Consider two-column (what works vs. what breaks) or progressive reveal

---

### Slide 3: What's Spec-Driven Development? (CONCEPT)
- **Type**: Core concept introduction
- **Content**:
  - Definition: doing hard work before code gets written
  - Key principle: "Context is king"
  - Why codebase indexing matters
- **Design notes**: Pull quote for "Context is king", diagram placeholder for context flow

---

### Slide 4: Writing the Spec (PROCESS)
- **Type**: Process/how-to
- **Content**:
  - Starting prompt example
  - 3-step process (ask, answer, iterate)
- **Design notes**: Numbered steps, prompt box styling for the example quote

---

### Slide 5: Generate Multi-Stage Plan (FRAMEWORK)
- **Type**: Framework explanation
- **Content**:
  - Core idea: break spec into PR-sized chunks
  - 3 key principles (incremental review, QA tasks, no monster PRs)
  - Mental model: "full feature, planned upfront, split into shippable pieces"
- **Design notes**: Visual timeline or stage diagram placeholder

---

### Slide 6: Generate Detailed Task List (FRAMEWORK)
- **Type**: Framework explanation (depth)
- **Content**:
  - Contrast with stages: "stages = what ships, tasks = how it's built"
  - Task characteristics: scoped for AI execution, clear acceptance criteria
- **Design notes**: Could pair with Slide 5 as a two-slide sequence; table or checklist format

---

### Slide 7: Sharing Specs (VALUE PROP)
- **Type**: Value proposition / collaboration
- **Content**:
  - Key message: specs as first-class artifacts
  - "Contract between humans, and between humans and AI agents"
  - Capability list (spec from terminal, upload, share, version)
- **Design notes**: Pull quote for "contract" statement, icon-based feature list

---

### Slide 8: Pass It to Your AI Agent (CHECKLIST)
- **Type**: Checklist / handoff criteria
- **Content**:
  - 3 requirements for a spec that works: codebase research, stages, file-by-file instructions
  - Outcome: agent builds the right thing
- **Design notes**: Checkmark icons, strong visual hierarchy

---

### Slide 9: Before/After Example (CASE STUDY)
- **Type**: Case study / proof
- **Content**:
  - Placeholder for concrete example (e.g., LiteLLM case study)
- **Design notes**: Side-by-side comparison layout, screenshots or code snippets

---

### Slide 10: Shotgun CTA (CTA)
- **Type**: Call to action
- **Content**:
  - Tool introduction: what Shotgun does
  - Example spec link
  - "Open source. BYOK."
  - Website link
- **Design notes**: Logo prominent, clear CTA buttons, link styling

## Design Cue Legend

| Cue | Meaning |
|-----|---------|
| `<!-- HERO SLIDE -->` | Full-bleed, bold typography, minimal text |
| `<!-- LIST SLIDE -->` | Bullet or icon-based list format |
| `<!-- PROBLEM SLIDE -->` | Tension/challenge framing, may use contrast layout |
| `<!-- CONCEPT SLIDE -->` | Core idea introduction, educational tone |
| `<!-- PROCESS SLIDE -->` | Step-by-step or numbered sequence |
| `<!-- FRAMEWORK SLIDE -->` | Methodology explanation, may include diagram |
| `<!-- VALUE PROP SLIDE -->` | Benefit-focused, feature highlights |
| `<!-- CHECKLIST SLIDE -->` | Requirements or criteria with checkmarks |
| `<!-- CASE STUDY SLIDE -->` | Example/proof, before-after or screenshots |
| `<!-- CTA SLIDE -->` | Call to action, links, branding |
| `<!-- PULL QUOTE -->` | Highlight a key phrase for emphasis |
| `<!-- DIAGRAM -->` | Placeholder for visual/diagram |
| `<!-- VERBATIM -->` | Do not edit this section; preserve exact wording |
